```

    #                                      if tag == "shutdown": break
    #                                      fn = payload
    #   send(idx, item) ×N  ──►            while True:
    #                                        item = recv(source=0, tag=0)
    #                                        if item is sentinel: break

    #   recv(result) ×N     ◄──              send((idx, result), dest=0, tag=1)
    #   send(sentinel) ×N   ──►            # back to outer while True

```

Known failure modes (summarize in docstring):

1. **Worker crash during map():** Root receives a `_WorkerError` wrapper. It
   drains remaining workers by sending sentinels and re-raises. Workers that
   have not yet received a sentinel may wait at `recv(source=0, tag=0)` until
   the drain completes — but the drain always happens (see lines ~119-128).

2. **Root exception before shutdown():** The caller's `try/finally` pattern
   (pyabc_wrapper.py, abc_smc_baseline.py) guarantees `cmap.shutdown()` fires.
   Without that pattern, workers block at `bcast(None, root=0)` forever. This
   was the Apr-8-2026 teardown fix.

3. **Worker crash BETWEEN map() calls** (during worker_loop's bcast wait):
   no liveness check. The next `bcast(("map", fn))` from root will hang
   because not all ranks participate. Job eventually killed by SLURM timeout.
   By design — no heartbeat. See `.plans/diagnose/mpi-evaluation.md` Risk
   section for the tradeoff rationale.

4. **Single-process mode** (`self.size <= 1`): `map()` bypasses all MPI calls
   and runs `[fn(item) for item in items]` sequentially. Used in local
   `--test` runs without mpirun.

Coordination model summary (one paragraph):

> CommWorldMap implements blocking parallel map over MPI COMM_WORLD using
> only `bcast`, `send`, and `recv` — no inter-communicators, no
> `Create_intercomm` / `Disconnect`. This avoids the ParaStation-MPI
> teardown hang observed with `MPICommExecutor` at high rank counts
> (Apr 4-8 2026; see `.plans/bug-fixes/previous-fixes.md`). Root
> broadcasts a task, dynamically distributes work items one at a time
> (for load balance), and collects results in submission order. Workers
> spin in `worker_loop()` until root sends a "shutdown" broadcast.
</rank_protocol_reference>
