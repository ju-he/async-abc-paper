<objective>
Add a pytest test to `experiments/tests/test_seeding.py` that verifies single-process determinism: running the `rejection_abc` method twice with the same config and seed produces the same output CSV row set. Satisfies REPR-02 per D-04 (scope: single-process methods only) and D-05 (pytest test, not a separate audit document per D-06).

Purpose: Seed determinism of `make_seeds` / `seed_everything` is already tested in isolation, but there is no end-to-end test that confirms a full runner invocation actually produces bit/row-identical outputs across two runs with the same seed. This gap would let silent non-determinism (e.g. dict ordering leaking into param sampling, a new random.random() call introduced without seeding) slip through.

Output: One new test function in `test_seeding.py` (D-05 discretion — goes in test_seeding.py since it's a seeding property test). Test:
1. Builds a minimal gaussian_mean config with `methods=["rejection_abc"]`, `base_seed=1`, `n_replicates=2`.
2. Runs `gaussian_mean_runner.py` in tmp_dir A.
3. Runs `gaussian_mean_runner.py` in tmp_dir B with the SAME config.
4. Asserts the two output CSVs have equal row sets on (method, replicate, seed, step, loss, all param columns).

            test_helpers.run_runner_main("gaussian_mean_runner.py", config_path, dir_b)
