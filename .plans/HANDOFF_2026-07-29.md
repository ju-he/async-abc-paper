## Hard-won gotchas — do not rediscover

- **Only the barrier arm needs sim-limiting.** A collective barrier needs
  identical per-rank call counts; wall-clock stops ranks independently
  (first-rank-hit) and deadlocks. Async has no barrier -> run it wall-limited.
- **Never give both arms the same budget.** `propulate_budget_mode=total_simulations`
  is a *per-worker* budget; with a persistent straggler that makes both arms
  straggler-gated and erases the async advantage entirely (measured: async
  8.0 sims/s sim-limited vs ~3200 wall-limited at 20x).
- **Size budgets from measured rates, not analytics.** Analytic estimates ignored
  MPI barrier latency and were ~4x off at factor 0.
- **A sim-limited run that hits its SLURM walltime dies with NO records.**
- Test-mode `clamp` *sets* `max_wall_time_s` when absent (deliberate — it bounds
  smoke runs); barrier runs are explicitly exempted.
- The runner's test-mode "Estimated full run ~273 h" is the **serial unsharded**
  aggregate — divide by 48.
- `submit_scaling_cpm.py` takes `output_dir` **positionally**, and its walltime
  estimator returns 0 s for sim-limited runs -> pass `--min-time`.
- `sbc_`-prefixed experiments resolve by convention (no registry entry needed);
  every other new experiment needs entries in **all three** registries
  (`run_all_paper_experiments`, `shard_finalizers`, `sharding`).
- rsync deploys must use **full destination paths** (a bare-file rsync drops the
  parent dir — this has bitten three times).
